# STARR Owner App — Permanent App Factory Team

## Owner rule
The Owner does not build, maintain, test, integrate, deploy, update, or routinely administer STARR apps. The Village owns this work. The Owner only performs actions that genuinely require owner authorization, payment, account ownership, legal approval, or platform permission.

## Permanent app team
These roles remain permanent members of the STARR Village after this app is finished:
- App Product Lead — roadmap, requirements, lifecycle
- App UX/UI Agent — phone-first experience and accessibility
- App Engineering Agent — implementation
- App Integration Agent — Zite, STARR Brain, GitHub/Codex, website, product/video/business systems
- Mobile/PWA Agent — installability, mobile compatibility and offline behavior
- App QA Agent — functional, visual, device and regression testing
- App Security Agent — authentication, permissions, privacy and threat checks
- App Release Agent — staging, release gates, deployment and rollback
- App Maintenance Agent — monitoring, bug fixes, dependency/runtime updates
- App Analytics Agent — usage, failures and performance
- App Support Agent — user-facing issues and support workflows
- App Factory Architect — reusable architecture for future STARR apps

## Mission
Build the STARR Owner App as the single phone control centre for the STARR ecosystem. It must link, where technically and securely possible, to:
Zite/MCC, STARR Brain, E-products, STARR Shop, Website, other STARR apps, Videos, Education, Research, Business/Finance, GitHub, Codex, agent/work queues, alerts, approvals, connections, backups, QC and reporting.

## Permanent lifecycle
Discover → design → build → integrate → test → security/QC → staging → owner gate only when genuinely required → release → monitor → maintain → improve → repeat.

## App factory rule
When another STARR app is needed, this same team designs/builds/tests/releases it and then remains responsible for its maintenance. Do not dissolve the team after a launch.

## No false status
An integration is only shown as LIVE after real verification. Failed or unavailable connections must be clearly marked and routed to the Village for repair.

## Owner-action gate
If owner authorization is genuinely required:
OWNER ACTION REQUIRED → exact action → owner completes it → Village resumes automatically.
